### Breaks (drift / missing FK / two-worlds / green-lie / orphan)

- **TYPE MISMATCH — exhibition_leads FK impossible**: `exhibitions.id` is `varchar` (UUID text, e.g. `"05702492-52ed-4c19-9c51-31e422c60797"`), but `exhibition_leads.exhibition_id` is `integer`. In `marketing-analytics-stubs.controller.ts:336`, the code does `parseInt(id, 10)` on the UUID which silently strips to the leading digits (e.g. `5702492`) — a completely different value. No FK constraint enforces this. Every lead insert lands with an `exhibition_id` that references nothing. `GET /exhibitions/:id/leads` then queries `WHERE exhibition_id::text = ${id}` (line 273) which casts the integer to text and compares to the UUID string — never matches. Leads are silently orphaned on both write and read.

- **FE-BE field drift — exhibition leads form**: `MarketingExhibitions.tsx:67` sends form fields `companyName`, `contactPerson` (camelCase). `ExhibitionLeadSchema` (stubs controller line 48) expects `name`/`full_name`/`company` (snake_case). Schema uses `.passthrough()` so it accepts but ignores `companyName`/`contactPerson`. INSERT at line 337 uses `dto.name ?? dto.full_name ?? ''` and `dto.company ?? null` — both come back `undefined`, so lead inserts with `name = ''` and `company = null` regardless of user input.

- **FE-BE field drift — social_api_configs**: `MarketingSettingsTypes.ts:6-15` defines `SocialApiConfig` with fields `apiKey`, `apiSecret`, `accessToken`, `pageId` (camelCase). `SocialApiSchema` at stubs controller line 59 accepts only `platform`, `bot_token`, `webhook_secret`, `is_active`, `settings`. The FE sends `apiKey`/`apiSecret`/`accessToken`/`pageId` which pass through `.passthrough()` but are NOT mapped in the INSERT at line 469 — only `bot_token` and `webhook_secret` are persisted. `apiKey` and `apiSecret` are silently dropped. GET response returns snake_case columns (`bot_token`, `page_id`), which the FE types as `apiKey`/`pageId` — always undefined in the UI.

- **AB-tests read-only orphan**: `marketing_ab_tests` table exists (0 rows). Only `GET /marketing/ab-tests` is implemented. No `POST`, `PATCH`, or `DELETE` routes exist in the entire marketing module. FE `MarketingExtended.tsx:45` reads the endpoint but only displays the list — no create button. Table will remain at 0 rows forever without a writer route.

- **AB-tests FE schema mismatch**: FE `MarketingExtendedTypes.ts:48` expects `{ name, variant, conversion, visitors, status }`. DB table has `variant_a`, `variant_b`, `conversions_a`, `conversions_b`, `impressions_a`, `impressions_b`. GET returns `SELECT *` so FE gets raw split-column rows with no `variant` or `conversion` or `visitors` fields — all render as `undefined` when data arrives.

- **No FK between exhibition_leads and exhibitions**: confirmed via `information_schema.table_constraints` — only CHECK constraints and PK; no FOREIGN KEY. The `crm_lead_id` column in `exhibition_leads` (integer) also has no FK to any CRM table.

- **PATCH /marketing/settings/social-api/:id silently skips bot_token/webhook_secret**: stubs controller line 490 UPDATE only sets `platform`, `is_active`, `settings` — never updates `bot_token` or `webhook_secret`. If a user wants to rotate a Telegram token via PATCH they must use the dedicated `POST /settings/setup-telegram-webhook` route, but the FE update form sends the full payload expecting a full update.

### 3-line summary

All five tables (`exhibitions`, `exhibition_leads`, `marketing_settings`, `social_api_configs`, `marketing_ab_tests`) exist in the live DB and CRUD routes are registered, but three critical breaks prevent correct operation: (1) `exhibitions.id` is varchar/UUID while `exhibition_leads.exhibition_id` is integer, so `parseInt` silently corrupts the FK on every lead insert and no leads are ever readable back; (2) FE sends camelCase fields (`companyName`, `apiKey`, `apiSecret`) that the BE schema ignores via passthrough, causing silent data loss; (3) `marketing_ab_tests` has only a GET route with no writer, and the FE interface shape (`variant`/`conversion`/`visitors`) does not match the split-column DB schema (`variant_a`/`conversions_a`/etc.), so even when rows exist they render as blank.
