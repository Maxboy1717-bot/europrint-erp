### Breaks (drift / missing FK / two-worlds / green-lie / orphan)

- **CRASH — createQuotation INSERT missing columns:** `sd-quotations.repository.ts:34` inserts into `sd_quotations (customer_id, title, total_amount, currency, valid_until, status, notes, items)` but live `sd_quotations` has neither `title` nor `items` columns (confirmed via `information_schema.columns`). Every POST /api/sd/quotations will fail with PostgreSQL error 42703 "column title does not exist".

- **CRASH — signContract missing column:** `drizzle-quotation.repo.ts:213` runs `UPDATE sd_contracts SET status='signed', signature_data=... WHERE id=...` but live `sd_contracts` has no `signature_data` column (columns are: id, order_id, contract_number, template_type, status, signed_at, signed_ip, pdf_url, valid_until, notes, created_at, updated_at, order_number, customer_id, papka_no). PUT /api/sd/contracts/:id/sign crashes on every call.

- **CRASH — updateKpiTarget table missing:** `drizzle-quotation.repo.ts:163` runs `UPDATE sd_kpi_targets SET...` but `sd_kpi_targets` table does not exist in live DB (`SELECT table_name FROM information_schema.tables WHERE table_name='sd_kpi_targets'` returns empty). PATCH /api/sd/kpi-targets/:id will error on every call.

- **POTENTIAL CRASH — cancelOrder missing column:** `drizzle-quotation.repo.ts:180` runs `UPDATE sales_orders SET status='cancelled', cancel_reason=...` but `cancel_reason` is not in live `sales_orders` columns (verified full column list — not present). PATCH+POST /api/sd/orders/:id/cancel will crash at runtime.

- **GREEN-LIE — getKpiTargets always returns empty array:** `sd-quotations.repository.ts:84-89` is `return Ok([])` with no DB access. GET /api/sd/kpi-targets always returns `[]` regardless of managerId. The table doesn't exist anyway, but the function silently pretends it worked. FE calls this route from KPITab.

- **GREEN-LIE — calculatePrice uses hardcoded base number:** `sd-quotations.service.ts:95` uses `QUOTATION_BASE_NUMBER` constant, never queries product pricing from DB. Returns computed price object that does not reflect actual product costs. POST /api/sd/calculate-price always returns the same base price regardless of productId.

- **DUPLICATE — convert-to-order vs convert:** `sd-quotations.controller.ts:136+143`: POST `/sd/quotations/:id/convert-to-order` and POST `/sd/quotations/:id/convert` both call `svc.convertToOrder(id)` — identical behavior. The `/convert` path is a redundant alias.

- **DUPLICATE — verb aliases (harmless but noisy):** PUT /send, PUT /approve, PUT /mark-paid, POST /cancel each mirror the PATCH/POST variants. Not functional bugs but inflate the route count and confuse Swagger.

- **TWO-WORLDS — customer FK absent:** `sales_orders.customer_id` (integer) has NO foreign key constraint to `sd_customers.id` (confirmed: only FK on sales_orders is `sales_orders_crm_lead_id_fkey → crm_leads`). The `sd_quotations.customer_id` also has no FK to `sd_customers` (`SELECT conname FROM pg_constraint WHERE conrelid='sd_quotations'::regclass` returns empty). Referential integrity is entirely code-enforced.

- **TWO-WORLDS — customer_* orphan cluster:** Tables `customer_orders`, `customer_contacts`, `customer_competitors`, `customer_complaints`, `customer_credit_limits`, `customer_documents`, `customer_interactions`, `customer_payments`, `customer_accounts` exist in live DB with 0 rows and no SD writer (only AI-alerts service reads `customer_orders`). These are a parallel customer schema with no active lifecycle. The active schema is `sd_customers` + `sd_customer_*`.

- **CONVERT FLOW FIELD MISMATCH:** `sd-quotations.repository.ts:126` extracts `quotation['customer_id'] ?? quotation['company_id']` to derive `companyId`, then at line 137 inserts that as `company_id` into `sales_orders`. But sd_quotations stores `customer_id` (which joins to `sd_customers.id`), and sales_orders has separate `customer_id` and `company_id` columns with different semantics. The convert flow writes to `company_id` instead of `customer_id`, meaning the converted order's `customer_id` remains NULL.

- **FE FIELD DRIFT — quotation camelCase:** FE `SdQuotation` type at `europrint/types.ts:64` uses `quotationNumber` and `totalAmount`, but live `sd_quotations` columns are `quotation_number` and `total_amount`. The GET /api/sd/quotations query returns raw DB snake_case rows. FE at `QuotationsTab.tsx:203` reads `q.quotationNumber` — will always be undefined. No snake-to-camel mapping in the repository.

- **ORPHAN TABLE — sd_kpi_targets:** Table does not exist in live DB. PATCH /api/sd/kpi-targets/:id crashes. GET /api/sd/kpi-targets returns green-lie [].

### Vision link (which of 22 visions this serves, % built)

This slice serves **Vision 1 — SD (Sales Distribution) order-to-delivery pipeline** and **Vision 4 — CRM/customer 360 relationship management**.

- Customer CRUD (sd_customers): ~85% built — full CRUD + contacts/interactions/documents/competitors/NPS/complaints all wire to real DB. Missing: no FK from `sales_orders.customer_id → sd_customers.id`, no FK from `sd_quotations.customer_id → sd_customers.id`.

- Overall slice: ~60% built.

### 3-line summary

The SD customers module is well-implemented with real DB CRUD for all 9 sub-resources (contacts, NPS, interactions, documents, competitors, complaints). Quotations have a critical INSERT bug: `createQuotation` references `title` and `items` columns that do not exist in live `sd_quotations`, making every new quotation creation crash with PG error 42703. Three additional crash-on-call paths exist: `signContract` (missing `signature_data` column in sd_contracts), `cancelOrder` (missing `cancel_reason` in sales_orders), and `updateKpiTarget` (table `sd_kpi_targets` does not exist). A structural two-worlds problem persists: `sd_quotations.customer_id` and `sales_orders.customer_id` have no FK to `sd_customers.id`, and the convert-quotation-to-order flow incorrectly populates `company_id` instead of `customer_id`.
