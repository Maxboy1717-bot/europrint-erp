### Breaks (drift / missing FK / two-worlds / green-lie / orphan)

- **GREEN-LIE: POST /api/crm/ai/nba/create-task (crm-ai-extended.controller.ts:137-141)** — returns `{created:true,taskId:Date.now()}` with zero DB write. FE `AIAnalysisPanel.tsx:59` calls this believing a task was created. The fake ID from `Date.now()` is never persisted to `crm_tasks` (5 real rows in DB, but none created via this endpoint).

- **GREEN-LIE: all CrmAiExtendedService methods** (crm-ai-extended.service.ts:13-128) — autofill (hardcoded Manufacturing/50-200/50M-200M), analyzeChurn (hardcoded risk_score:0.42), suggestAutoTasks (hardcoded 3 task titles), getAiLeads (empty array), getAiNba (empty array), getAiQuickScore (hardcoded score:65). None of these read from DB.

- **Silent data mismatch (GREEN-LIE effect): forecastDeal** (crm-ai.service.ts:72,77) reads `deal['expected_amount']` but `crm-ai.repository.ts:72` selects the column aliased as `amount` (field key `amount`, not `expected_amount`). `expected_amount` is always `undefined → 0`, so `forecast_amount` always computes as 0, and the "large deal threshold" adjustment never fires.

- **Schema drift: crmDeals.expected_amount** — `crm-ai.repository.ts:107` uses `crmDeals.expected_amount` in a SQL fragment for `getDealDashboard`. This column does not exist in the Drizzle schema (crm-pipelines.ts defines `opportunity` and `forecastAmount`). TypeScript resolves `crmDeals.expected_amount` as `undefined`; Drizzle silently omits it, producing incorrect `pipeline_value: 0` in all dashboard queries.

- **No-op score writes: updateLeadScore/updateLeadScoreSimple** (crm-ai.repository.ts:42,64) — these methods are intentionally no-ops (noted in comments: "crm_leads has no ai_score column"). Confirmed: live DB `crm_leads` has no `ai_score` column. All score computations are in-memory only.

- **Score field key mismatch: scoreLead()** (crm-ai.service.ts:36-47) checks `lead['email']`, `lead['phone']`, `lead['company_id']`. However, the repository at crm-ai.repository.ts:22-38 selects only `contact_email`, `contact_phone` — not `email`, `phone`, `company_id`. All three checks always return falsy; scoring starts at 30 and can only grow from activity count and recency.

- **MISSING routes: 5 FE endpoints return 404** — ExtendedAIPanel.tsx calls POST voice/analyze-call, POST chat/respond, GET extended/churn/analyze, POST auto-tasks/create, and GET supervisor-dashboard (wrong path prefix). The service methods exist in CrmAiExtendedService but no controller routes expose them.

- **DUPLICATE route concept: POST nba/:entityType/:entityId** exists on BOTH `crm-ai.controller.ts:93` (`/api/crm/nba/...`) and `crm-ai-extended.controller.ts:146` (`/api/crm/ai/nba/...`). FE only calls the `/crm/ai/` path; the `/crm/` path is an orphan route. Same repo method behind both.

- **DUPLICATE concept: POST leads/:id/scoring-v2** exists at `/api/crm/leads/:id/scoring-v2` (crm-ai.controller.ts:58) and `/api/crm/ai/leads/:entityId/scoring-v2` (crm-ai-extended.controller.ts:231). FE calls only the latter. Former is orphaned.

- **No actual AI integration**: neither controller slice calls any LLM/ML service. All "AI" responses are either hardcoded JSON blobs (extended service) or simple heuristic scoring functions. Vision #13 (voice/email comms) shows email/SMS as CrmCommsService which logs to crm_activities — not a real email delivery service (no SMTP/API call confirmed: crm-comms.service.ts:17-19 returns `{sent:true,...}` without external call).

### 3-line summary

The CRM AI-extended slice has 12 routes where 9 are GREEN-LIE (hardcoded or no-op responses with no DB interaction), 1 is a pure fake-ID green-lie (`nba/create-task` returns `Date.now()` as taskId with zero DB write), and only ~3 routes perform real DB reads. Five endpoints called by the FE (`ExtendedAIPanel.tsx`) return 404 because the service methods exist but no controller routes are wired. The AI scoring machinery has compounding data-path bugs (field key mismatch `email` vs `contact_email`, `expected_amount` property undefined in Drizzle schema, score writes are no-ops), so even the "real" routes return functionally incorrect results.
