### Breaks (drift / missing FK / two-worlds / green-lie / orphan)

- **CRITICAL — fi_payments missing:** `FinanceOpsRepo.recordPayment` (drizzle-finance-ops.repo.ts:86) executes `INSERT INTO fi_payments ...` but `fi_payments` does NOT exist in the live DB. Any call to `POST /api/finance/payments/record` will crash with a PostgreSQL relation-not-found error at the DB level.

- **GREEN-LIE — POST /verify:** `finance-payments.controller.ts:125` returns `{ message: 'Payment verified', paymentId }` with no DB write. `FinanceVerifyPaymentDto` is parsed but then completely ignored. Route pretends to verify but does nothing.

- **GREEN-LIE — GET /outstanding:** `finance-payments.controller.ts:136` returns `{ data: { invoiceId, outstanding: 0 } }` hardcoded — no query against fi_invoices or any other table. Always claims outstanding is zero.

- **VERB-DUPLICATE approve:** Both `PATCH /api/finance/payments/:id/approve` (line 88) and `POST /api/finance/payments/:id/approve` (line 141) call `this.actionsSvc.approvePayment(Number(id), user.id)` identically. Same business action, two HTTP verbs, same path pattern. One is dead weight.

- **TWO-WORLDS — payment tables:** Three separate payment storage layers exist with no FK bridge:
  - `fi_payments` (referenced by record-payment flow, table missing)
  - `payments` (used by `/api/fi/payments`, Drizzle schema `schema-finance-invoicing.ts:52`)
  - `customer_payments` (used by approve flow, schema-compat-5.ts:9)
  - `finance_payments` (exists in DB, no writer in code — orphan)
  None of these tables share FK links; the approve flow writes `customer_payments` but `recordPayment` writes `fi_payments`. The GET /listPayments actually queries `fi_invoices WHERE status='paid'` (not any payments table) — so payments are read from invoice status, not from a payments ledger.

- **TWO-WORLDS — GL entries:** `recordPayment` posts GL to `entries` table (canonical, via DrizzleGlPostingRepository), while `FinanceInvoiceRepo.saveGlEntry` inserts into `gl_journal_entries` (secondary unused path). Memory doc confirms: `entries` is canonical, `gl_journal_entries`+`gl_lines` unused.

- **FE drift — no FE calls `/api/finance/payments`:** The FE page `FinanceExtended.tsx:79` calls `/api/fi/payments` (the fi.controller path), NOT `/api/finance/payments`. The entire `FinancePaymentsController` is unreachable from the FE. `SDSalesPayments.tsx` calls `/api/sd/payments/*` (SD module, separate controller). No FE page calls `POST /api/finance/payments/record`, `POST /api/finance/payments/:id/verify`, or `GET /api/finance/payments/:id/outstanding`.

- **ORPHAN — finance_payments table:** `finance_payments` table exists in live DB (0 rows) but no Drizzle pgTable schema definition or INSERT statement references it anywhere in the codebase. Pure orphan.

### 3-line summary

The `FinancePaymentsController` (`/api/finance/payments`) has 7 routes: one real list (reads fi_invoices status), one real approve (customer_payments), one real record that hard-crashes because `fi_payments` table was never created in the live DB, two green-lies (verify/outstanding return hardcoded), one 501-stub root POST, and a verb-dup PATCH+POST approve pair. The FE calls `/api/fi/payments` (separate `FiController`) not this controller, so the entire finance-payments controller is orphaned from the UI. Three parallel payment tables (`fi_payments`, `payments`, `customer_payments`) plus an orphan `finance_payments` represent a four-way split with no FK bridge and no canonical payment ledger.
