### Breaks (drift / missing FK / two-worlds / green-lie / orphan)

- **TWO-WORLDS campaigns**: `campaigns` table (uuid PK, `title` col, `created_by` uuid) vs `marketing_campaigns` (varchar(36) PK, `name` col, `created_by` integer). Both exist in DB with 0 rows. `DrizzleCampaignRepository` (drizzle-campaign.repo.ts:16) still writes to old `campaigns` table. The HTTP controller layer (marketing.controller.ts:73) was rerouted to `CampaignsService` / `CampaignsRepository` which writes `marketing_campaigns`. The CQRS command handlers (create-campaign.handler.ts) still use `CAMPAIGN_REPO` → `DrizzleCampaignRepository` → writes old `campaigns` table. The two write paths diverge silently.

- **GREEN-LIE analytics**: `GET /api/marketing/analytics/campaigns` (marketing-analytics.controller.ts:175) returns `impressions: 0, clicks: 0, roi: 0` for every campaign. FE MarketingCampaigns.tsx shows these fields. No tracking tables exist.

- **GREEN-LIE getCampaignStats**: `GET /api/marketing/campaigns/:id/stats` (marketing-content.controller.ts:36) always returns `impressions: 0, clicks: 0, conversions: 0, roi: 0` regardless of id (drizzle-marketing-ext.repo.ts:29). FE MarketingCampaigns.tsx:48 calls this on every campaign detail open.

- **501-STUB called by FE** — 6 stubs that break live FE flows:
  - `POST /api/marketing/content/ai-generate` (stubs:114) — FE MarketingContent.tsx:103
  - `POST /api/marketing/churn-risk/ai-signal` (stubs:150) — FE MarketingDashboardDialogs.tsx:129
  - `GET /api/marketing/ai-assistant` (stubs:160) — FE MarketingDashboardPanels.tsx:25
  - `POST /api/marketing/leads/recalculate-scores` (stubs:175) — FE MarketingLeads.tsx:128
  - `POST /api/marketing/leads/:id/convert-to-crm` (stubs:181) — FE MarketingLeads.tsx:117
  - `POST /api/marketing/inbox/ai-reply/:id` (stubs:234) — FE MarketingSocialInbox.tsx:78
  - `POST /api/marketing/website/blog/ai-generate` (stubs:535) — FE MarketingWebsiteCMS.tsx:88

- **DRIFT `getLeadsBySource`**: `GET /api/marketing/analytics/audience` calls `getLeadsBySource()` but drizzle-marketing-ext.repo.ts:213 groups by `marketingLeads.status` not the `source` column. The `marketing_leads` table has a real `source` column; the result is mislabeled.

- **DRIFT leads `campaignId` type mismatch**: `LeadsService.create` (leads.service.ts:46) maps `dto.campaignId` → `marketingLeads.campaignId` which Drizzle schema has as `varchar`. The `marketing_leads.campaign_id` live column is `varchar` — OK. But `MarketingAnalyticsController.createLead` (analytics.controller.ts:101) passes raw body through `MarketingLeadSchema` which uses `.passthrough()` — no enforcement of campaignId format.

- **ORPHAN tables** (0 rows, no writer):
  - `marketing_ads` — no code reference in marketing module
  - `marketing_budget_items` — superseded by `marketing_budget_lines`; no code reference
  - `marketing_content` — superseded by `marketing_content_posts`; no code reference

- **Route collision `PATCH /api/marketing/content/posts/:id`**: declared in both `marketing-content.controller.ts:126` (PATCH) and `marketing-content.controller.ts:67` (PUT) calling the same `updateContentPost`. The PATCH in analytics controller:126 is an additional third definition for the same route shape. NestJS resolves by registration order — silent redundancy.

- **`DrizzleMarketingExtRepository.getCampaignStats`** (drizzle-marketing-ext.repo.ts:28) uses `eq(marketingCampaigns.id, id)` where id is `number` (cast by controller `Number(id)`), but `marketing_campaigns.id` is `varchar(36)` uuid. The query will always return 0 rows when called from `GET /api/marketing/campaigns/:id/stats` because uuid ≠ integer. This is a latent type error masked by the fallback `{ id, impressions: 0, ... }`.

- **MISSING route `PUT /api/marketing/budget/:id`** (marketing-group2.controller.ts:175) uses `unwrapOrThrow` from `svc.updateBudgetLine`. The FE MarketingBudget.tsx:43 only calls `POST /budget` and `DELETE /budget/:id` — no FE `PUT /budget/:id` call found, so the PUT update endpoint is BE-only (no FE caller). Minor orphan BE route for budget update.

### 3-line summary

Marketing has ~100 routes across 5 controllers; the large majority write to real DB tables (all 0 rows, build-stage data). The biggest structural break is the two-worlds campaigns split: `marketing.controller` routes through `CampaignsService` → `marketing_campaigns` while the CQRS command handlers (`DrizzleCampaignRepository`) still write to the old `campaigns` table (uuid PK, `title` field) — writes from the two paths will never reconcile. Six FE-called endpoints are 501 stubs (AI-generate, convert-to-CRM, recalculate-scores, ai-reply, ai-assistant, churn-risk/ai-signal), and all analytics numeric fields (impressions, clicks, ROI) are hardcoded zeros creating green-lie dashboards.
