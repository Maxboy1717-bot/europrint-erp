### Breaks (drift / missing FK / two-worlds / green-lie / orphan)

- **GREEN-LIE: POST /qc/inspections** (`qc-inspections.controller.ts:77-82`) — calls `commandBus.execute(new CreateInspectionCommand(...))` but `CreateInspectionCommand` has NO `@CommandHandler` registered anywhere in `qc.module.ts` (commandHandlers array at line 62-67 omits it). The command class is defined at `submit-inspection.command.ts:14` but never handled. The CQRS bus will throw/silently return undefined. No DB write occurs.

- **TWO-WORLDS: qc_inspections Drizzle schema vs live DB** — Drizzle schema (`schema-wms.ts:156-179`) declares `id: uuid`, `inspector_id: uuid references users.id`, `reference_id: uuid NOT NULL`. Live DB has `id: integer (serial)`, `inspector_id: integer`, `reference_id: uuid`, plus extra columns `order_id integer`, `result varchar`, `pass_count`, `fail_count`, `total_count`, `inspected_at`, `attachments text`. The ORM INSERT path (`execQcInspectionUpsert`) will fail at runtime because it tries to insert a UUID string into an integer PK column. The workaround used in `qc-new.repository.ts:206-217` is raw SQL `WHERE id = ${Number(id)}` which correctly treats `id` as integer — proving the code author knows the mismatch.

- **TWO-WORLDS: qc_defects id type** — Drizzle `qc_defects` schema uses `id: text`. Live DB `qc_defects.id` is `integer`. `DrizzleDefectRepository.saveDefect` at line 79 inserts a random `Math.random().toString(36)` string id — this will fail on the integer column constraint. `ReportDefectHandler:67` generates the id via `generateId()` which produces a base-36 alphanumeric string, incompatible with integer PK.

- **STUB: SoSampleRequestedListener** (`so-sample-requested.listener.ts:22-33`) — handler body is just a log + empty comment "Lab test creation logic". Trigger 4 (SO sample requested → Lab test created) is a no-op. No `qc_lab_tests` insert occurs.

- **DRIFT: QcPassedListener uses `lookupRows.rows[0]`** (`qc-passed.listener.ts:44`) — `runQuery` returns `{rows}` not a flat array; but the pattern is consistent with the helper. However `sales_orders` table exists in DB but has 0 rows — so the lookup always falls through the early-return guard at line 45, meaning **FG receipt after QC pass never fires in practice** even if qc_inspections had data.

- **FE DRIFT: `/api/qc/tests/:orderId`** — FE `QCApproval.tsx:63` calls `GET /api/qc/tests/${selectedOrder.id}` but no such route exists in any QC controller. This call silently returns `[]` via the try/catch at line 61-66 in the FE.

- **FE DRIFT: QCDashboard approve/reject call** — FE `QCDashboard.tsx:50,65` calls `PATCH /api/qc/inspections/:id` with `{status:"approved"}` / `{status:"rejected"}`. BE `QcInspectionsController.updateInspection` at controller:101 handles this — it delegates to `QcNewService.updateInspection` which calls raw SQL UPDATE by `Number(id)`. This works IF the id is numeric, but the FE passes inspection IDs from `qc_inspections` rows (which have integer PKs in live DB). Functionally real but the status value "approved" is not in the declared status enum ('pending','in_progress','on_hold','passed','failed') — the COALESCE UPDATE will still write it since the raw SQL has no enum check.

- **ORPHAN: qc_certificates, qc_spc_data, qc_supplier_quality** — All have 0 rows and no writer found in code. The `qc_spc_data` Drizzle schema has an ORM table mapped but only reads (`findSpcReadings`, `getSpcChartData`) — no INSERT path exists.

- **DUPLICATE ROUTES: approve/reject** — Each of approve/finance, approve/qc, reject, inspector-submit has both PATCH and POST variants (6 routes doing identical things). These are verb-alias duplicates to accommodate FE clients that send either verb.

- **EVENT NO-OP: LabTestPassedEvent** — Declared at `domain/events/index.ts:40-46` with comment "No production code currently publishes this event". The PP `DesignLabCompletedListener` subscribes but will never fire.

### 3-line summary

The QC inspection submit/approve/reject chain has real DB writes via `_setQcStatus` (raw SQL) and `SubmitInspectionHandler` (transaction + upsert), but the `POST /qc/inspections` (create) route is a green-lie because `CreateInspectionCommand` has no registered CQRS handler and will silently fail.
A deep schema two-worlds exists: the Drizzle `qc_inspections` schema defines `id` as `uuid` and `inspector_id` as `uuid → users.id`, but the live DB has both as `integer`, so any ORM INSERT path (`execQcInspectionUpsert`) will throw a type error at runtime; workarounds using raw SQL `WHERE id = ${Number(id)}` confirm the author is aware.
Three QC tables (`qc_certificates`, `qc_spc_data`, `qc_supplier_quality`) have no writer at all (orphan), the FE calls a non-existent `/api/qc/tests/:id` route, and the QcPassedEvent→FG-receipt chain never fires because `sales_orders` is empty.
