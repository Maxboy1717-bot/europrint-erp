### Breaks (drift / missing FK / two-worlds / green-lie / orphan)

- **DRIFT — inbox/stats field name mismatch**: `marketing-analytics-stubs.controller.ts:188` GET `/marketing/inbox/stats` returns `{total, unread, pending, resolved, openRate}`. FE `MarketingSocialInboxTypes.ts:39-43` expects `{totalConversations, openConversations, unreadCount}`. All three stat values render as `undefined`/0 in `MarketingSocialInbox.tsx:132-142`. The FE inbox stats panel is silent/blank.

- **DRIFT — POST content/posts body vs content field**: `marketing-content.controller.ts:52` uses `CreateContentPostDtoSchema` which expects field `content` (`marketing-ext.dto.ts:11`). FE `MarketingContent.tsx:67` sends `{ title, body, platform, ... }` — the field is named `body`, not `content`. The Zod schema strips unknown keys → `content` is undefined on insert → all created posts have null content.

- **GREEN-LIE — POST /marketing/inbox/conversations/:id/reply**: `marketing-analytics-stubs.controller.ts:217` body parsing uses `dto.message ?? dto.content` but FE `MarketingSocialInbox.tsx:67` sends `{ text: replyText }`. Neither `message` nor `content` is present → stored as empty string. Reply appears to succeed (201) but text is always "".

- **501-STUB FE gap — POST /marketing/content/ai-generate**: `marketing-analytics-stubs.controller.ts:114-115`. `MarketingContent.tsx:103` calls this on "AI bilan yaratish" button. Returns 501 — live user-facing gap.

- **501-STUB FE gap — POST /marketing/inbox/ai-reply/:id**: `marketing-analytics-stubs.controller.ts:234-235`. `MarketingSocialInbox.tsx:77` calls this on AI reply button. Returns 501 — live user-facing gap.

- **DUPLICATE route — POST /marketing/website/blog/:id/publish**: `marketing-analytics-stubs.controller.ts:527` (PATCH) and `marketing-group2.controller.ts:123` (POST) both handle publish. Different HTTP verbs on same path → NestJS registers both; only POST is called by group2 but stubs controller's PATCH overlaps. Canonical = group2 POST.

- **DUPLICATE concept — analytics/audience vs getLeadsBySource**: `marketing-analytics.controller.ts:184` calls `getLeadsBySource()` which actually groups by `marketingLeads.status` (not `source`) — `drizzle-marketing-ext.repo.ts:216`. Column name used as grouping key is wrong (should be `.source`).

- **TWO-WORLDS — content tables**: Three content tables exist in the live DB with no FK links: `marketing_content_posts` (used by BE), `marketing_content` (orphan Drizzle table from older schema), and `content_posts` (another orphan Drizzle table). All have 0 rows. No cross-reference or migration. FE only ever calls `/marketing/content/posts` → `marketing_content_posts`.

- **ORPHAN — social_conversations**: Table exists (0 rows) but has NO INSERT route. The inbox UI in `MarketingSocialInbox.tsx` can only read (empty) and PATCH status — no way to create a conversation from this module (conversations must come from an external social webhook that is not wired).

- **ORPHAN — marketing_ab_tests**: Table exists (0 rows), GET route reads it, but there is no POST/PUT route to create A/B tests. `MarketingExtended.tsx` likely shows empty list forever.

- **TypeScript error — marketing.controller.ts:99,117,143**: `AuthenticatedUser` type is used but not imported. Missing `import { AuthenticatedUser } from '@common/types/user.types'`. Compiles only if global type is resolved via tsconfig paths or `any` fallback.

- **marketing.controller.ts imports CQRS commands/queries but does not use them**: `CreateCampaignCommand`, `UpdateCampaignCommand`, `LaunchCampaignCommand`, `GetCampaignsQuery`, `GetCampaignQuery`, and `throwFromError` are imported but the controller delegates entirely to `CampaignsService`. Dead imports add maintenance noise.

### 3-line summary
