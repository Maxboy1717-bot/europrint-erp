### Muammolar (5 tomon mos kelmagan joylar)

- **P0 — Leads by-id butun zanjiri buzilgan (id-tur drift).** `leads.service.ts:37,57,64` `id:number` + controller `marketing-analytics.controller.ts:107,115,123` `Number(id)`; repo `leads.repository.ts:43,61,70` `eq(marketingLeads.id, id)`. Live `marketing_leads.id = character varying(36) uuid` (DB tasdiq), lekin stub `schema-compat-3.ts:154` `id: integer`. FE `MarketingLeads.tsx:44` `editId: string`. Natija: `Number("<uuid>") = NaN` → findOne/update/delete/patch/status hech qachon qatorni topmaydi → 404 yoki jim no-op. List/create ishlaydi (id lookup yo'q), shu sabab "yashil ko'rinadi". Verify: lead yarat → tahrirlash/o'chirish bosib ko'r → saqlanmaydi.
- **P1 — Route-collision: `/marketing/leads/loss-analysis` hech qachon ishlamaydi.** `marketing-analytics.controller.ts:104` `@Get('leads/:id')` (getLead) `:211` `@Get('leads/loss-analysis')` dan OLDIN e'lon qilingan. NestJS e'lon tartibida moslaydi → `loss-analysis` `getLead` ga `id="loss-analysis"` bo'lib tushadi → `Number(...)=NaN`. FE `MarketingLeads.tsx:80` `/api/marketing/leads/loss-analysis` chaqiradi → LossAnalysisPanel hech qachon real data olmaydi. Tuzatish: loss-analysis route'ni `:id` dan oldinga ko'chirish.
