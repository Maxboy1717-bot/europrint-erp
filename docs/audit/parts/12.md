### Breaks (drift / missing FK / two-worlds / green-lie / orphan)

- **TWO-WORLDS (defects)**: `GET /qc/defects` (GetDefectsHandler line 27) and `GET /qc/reclamations` (GetReclamationsHandler line 27) both query `quality_defects_camera` — while canonical brak/defect data is expected in `qc_defects` and `qc_reclamations`. FE `DefectManagementPage.tsx:39` calls `/api/qc/defects/extended` which returns `qc_braks` rows. Three different tables serve the "what defects exist" question.

- **MISSING TABLE — qc_approvals**: `qc-defects-extended.repository.ts:97,107,116` — all three approvals routes (`GET/POST /qc/approvals`, `PATCH /qc/approvals/:id`) will throw PostgreSQL "relation does not exist" 500 on every call. Table confirmed absent from live DB.

- **STRING-VS-INT id mismatch on save**: `create-reclamation.handler.ts:52` generates a random alphanumeric string id; `qc_reclamations.id` is `integer` (confirmed). Same issue: `report-defect.handler.ts:67` generates string id; `qc_defects.id` is `integer`. Every `POST /qc/defects` and `POST /qc/reclamations` will throw a cast error on INSERT.

- **material_card_id column missing**: `qc-defects-extended.repository.ts:67` — `createSupplierQuality` INSERT includes `material_card_id` column which no longer exists in `qc_supplier_quality` (confirmed). `POST /qc/supplier-quality` always fails with 500.

- **deleted_at column missing**: `qc-defects.controller.ts:143` — `GET /qc/braks/cost-impact` filters `WHERE deleted_at IS NULL OR deleted_at IS NULL` — `qc_braks.deleted_at` does not exist. Query throws 500.

- **root_cause_id missing from qc_reclamations**: `qc-defects-extended.repository.ts:124` — `PATCH /qc/reclamations/:id` UPDATE references `root_cause_id` column; confirmed absent from `qc_reclamations`. Will fail with 500.

- **Unregistered CQRS handlers for string-type queries**: `qc-defects.controller.ts:85,99` — `commandBus.execute({type:'GetDefectStatsQuery'})` and `{type:'GetDefectByIdQuery'}` — NestJS CQRS dispatches by class constructor, not by a `type` string literal. No `@QueryHandler(...)` class registered for these object shapes. Routes silently return undefined or throw.

- **FE field mismatch on GET /qc/defects/extended**: `DefectManagementPage.tsx:14-24` — expects fields `estimatedLossUzs`, `decision`, `workCenterName`, `reportedAt`. `GET /qc/defects/extended` returns `qc_braks` rows (via `listBraks` alias, `qc-defects-extended.controller.ts:53`) which have `cost_impact`, `stage`, `created_by`, `brak_date` — none of the expected FE fields. All KPI values will be 0 / empty.

- **FE calls missing route POST /qc/tests**: `QCApproval.tsx:146` — calls `POST /api/qc/tests`. No controller in the QC module exposes `/qc/tests` as a writable endpoint. Request will return 404.

- **FE calls missing route GET /qc/tests/:id**: `QCApproval.tsx:63` — calls `GET /api/qc/tests/:id`. Same issue — no such route exists.

- **Hardcoded SPC capability**: `qc-new.repository.ts:191` — `processCapability: { cp: 1.33, cpk: 1.21, status: 'capable' }` is always hardcoded regardless of actual measurement data. Vision #10 requires real Cp/Cpk computation.

- **Two brak writers, same table**: `DrizzleDefectsRepository.createBrak` (drizzle-defects.repo.ts:59) and `QcDefectsExtendedRepository.createBrak` (qc-defects-extended.repository.ts:45) both INSERT into `qc_braks`. The extended repo uses raw SQL and omits several columns the Drizzle schema requires. The Drizzle repo uses ORM insert. No coordination — duplicate insert paths with different fields.

- **VERB DUPLICATE — POST+PATCH for approve/reject/submit**: `qc-defects.controller.ts:177/198/219/243` — PATCH and POST versions for `/qc/approve/finance/:orderId`, `/qc/approve/qc/:orderId`, `/qc/inspector-submit/:orderId` call identical handlers. FE and tests only use one verb. The other is dead weight.

- **Orphan tables with no writers**: `qc_defects_extended`, `qc_ai_trend`, `qc_material_tests`, `qc_parameter_definitions` exist in the DB but have no code that writes to them or reads from them in the QC module.

### Vision link (which of 22 visions this serves, % built)

Vision #9 (Brak tracking — defect logging, rework decisions, cost impact) and Vision #10 (QC process — inspections, reclamations, supplier quality, SPC/DPMO analytics).

- Vision #9: ~30% — `qc_braks` table and write path exist, FE create dialog works (`POST /qc/braks` real), but cost-impact route crashes (deleted_at), GET /qc/defects/extended returns wrong table shape, no rework decision update endpoint.
- Vision #10: ~35% — Inspections CRUD complete and wired, reclamation stats work, SPC data read works, DPMO calculation works. But: reclamation CREATE crashes (string-vs-int id), approvals subsystem completely broken (table missing), supplier quality write broken (material_card_id), GET /qc/defects and GET /qc/reclamations return camera-AI table not domain table.

### 3-line summary

The QC defects/braks slice has extensive route coverage (60+ endpoints across 7 controllers) but five runtime-breaking bugs block core flows: `qc_approvals` table is missing (all three approval endpoints throw 500), `material_card_id` drift makes POST /qc/supplier-quality crash, string-vs-integer PK mismatch means POST /qc/defects and POST /qc/reclamations always fail on INSERT, and the canonical GET /qc/defects and GET /qc/reclamations routes both read from `quality_defects_camera` (the AI camera table) instead of their respective domain tables, creating a two-worlds split.
The FE DefectManagementPage also hits a field-mismatch drift: it expects `estimatedLossUzs`/`decision` but the endpoint returns `qc_braks` raw rows, so all KPI cards show 0. All 19 QC DB tables have 0 rows (build stage), but several tables have no writer at all (`qc_defects_extended`, `qc_ai_trend`, `qc_material_tests`, `qc_parameter_definitions`) and `qc_certificates` has no CREATE endpoint.
