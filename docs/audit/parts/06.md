### Breaks (drift / missing FK / two-worlds / green-lie / orphan)

- **TYPE MISMATCH — social_messages.conversation_id**: Drizzle schema (`lib/db/src/schema/marketing-schema.ts:398`) declares `conversationId` as `varchar(36)`, but live DB has `conversation_id INTEGER`. Controller code at `marketing-analytics-stubs.controller.ts:226,240` compensates with `parseInt(id, 10)` — however `social_conversations.id` is varchar (UUID-style), so `parseInt` on a UUID produces `NaN`. The guard `isNaN(convId) ? 0 : convId` then uses `0` as the FK, returning empty results every time a real UUID conversation id is passed.

- **FE-BE field name drift — inbox stats**: FE type `InboxStats` at `artifacts/erp-dashboard/src/pages/MarketingSocialInboxTypes.ts:39-43` expects `{ totalConversations, openConversations, unreadCount }`. BE `getInboxStats()` at `drizzle-marketing-ext.repo.ts:354` returns `{ total, unread, pending, resolved, openRate }`. Fields never match; FE will show `undefined` for all three stats.

- **501-STUB with active FE caller — AI reply**: `POST /api/marketing/inbox/ai-reply/:id` (stubs.controller.ts:255-256) is an explicit `stub()` returning 501. FE `MarketingSocialInbox.tsx:78` has `aiReplyMutation` calling this. Vision #17 SMM-AI oversight is exactly this; 0% built for AI path.

- **GREEN-LIE pattern — PR create id**: `POST /api/marketing/pr` at stubs.controller.ts:400 generates `id = 'PR-${Date.now()}'` (string, not UUID). The table `pr_activities.id` is `varchar`. This persists correctly but the id format is non-standard and will collide if two requests arrive within the same millisecond.

- **ORPHAN CQRS repo — campaigns table**: `drizzle-campaign.repo.ts:15` imports `campaigns` from `@shared/db` which targets the orphan `campaigns` table (uuid PK, 0 rows). This repo is wired to CQRS handlers (`GetCampaignsHandler`, `LaunchCampaignCommand`, etc.) but the HTTP controller bypasses it entirely (marketing.controller.ts:100-103) in favor of `CampaignsRepository → marketing_campaigns`. The CQRS handlers are registered in the module but no HTTP route dispatches to them for write operations, making the entire CQRS layer dead code.

- **TWO-WORLDS — campaigns**: `campaigns` table (uuid PK, 0 rows, no writer) vs `marketing_campaigns` (varchar PK, canonical, has writer). The CQRS aggregate + handler still references the orphan table. The `DrizzleCampaignRepository` is still injected and registered but never called through active routes.

- **marketing_leads schema drift**: Live DB `marketing_leads.campaign_id` is `integer`, `crm_lead_id` is `integer`, `assigned_to` is `integer`. Drizzle schema at `lib/db/src/schema/marketing-schema.ts:147,151,152` declares these as `varchar`. Drizzle ORM queries that filter on these columns by integer value will produce type coercion issues.

- **getInboxStats reads via ORM but Drizzle socialConversations schema is consistent**: `drizzle-marketing-ext.repo.ts:356` uses the Drizzle `socialConversations` table which correctly maps `unread_count` integer. This path works. The break is the downstream `getConversationMessages` + `replyToConversation` which uses raw SQL with the broken `parseInt` on UUID id.

- **BE route /api/marketing/inbox/conversations returns camelCase from DB `*` select**: The `SELECT *` at stubs.controller.ts:214 returns snake_case column names from PostgreSQL. FE `SocialConversation` interface at `MarketingSocialInboxTypes.ts:9-24` expects camelCase (`contactName`, `isAiHandling`, `lastMessage`, `lastMessageAt`, `unreadCount`). FE will receive `contact_name`, `is_ai_handling`, etc. — all undefined.
