## Reality-check discrepancies vs. V6 audit

The audit report's "broken APIs" list was generated by a static script that flagged
URL templates like `/api/hr/referrals/:id`, but didn't always distinguish between
"missing endpoint" and "endpoint present with literal path that the script normalized".

Findings by page:

- **`/hr/gamification`** — audit flagged `/api/hr/gamification/leaderboard?period=:id`.
  Reality: `GamificationController.leaderboard(@Query('period'))` exists at
  `apps/api/src/modules/hr/gamification/gamification.controller.ts:48`. The `?period=:id`
  in the audit is the normalizer treating the query value as an id. **NOT BROKEN.**

- **`/hr/reception`** — audit flagged `/api/hr-v2/reception/badge/:id`.
  Reality: `ReceptionController.validateBadge(@Param('badge_number'))` exists at
  `apps/api/src/modules/hr/reception/reception.controller.ts:72`. **NOT BROKEN.**

- **`/hr/daily-reports`** — audit lists 4 broken. Reality is more nuanced:
  - `GET /api/hr-v2/daily-reports/employee?employeeId=X&limit=14` is a **stub** in
    `daily-report.controller.ts:78-79` returning `{ data: [], total: 0 }`.
  - `GET /api/hr-v2/daily-reports/stats?date=X` **exists** at line 63.
  - `GET /api/hr-v2/daily-reports/department/:id?date=X` is **missing** (only
    `Get('department')` stub at line 81-82 with no `:id`).
  - `GET /api/hr-v2/daily-reports/by-date?type=...` exists at line 68 but ignores `type`.

- **`/hr/onboarding`** — audit flagged `/api/hr/onboarding-checklists/:id`. Reality:
  the path is served by a stub in `hr-dashboard.controller.ts:158-161` returning
  `{ items: [], total: 0 }`. No PATCH/POST handler exists. **CONFIRMED BROKEN.**

- **`/hr/offboarding`** — audit flagged `/api/hr/offboarding/cases?status&search`.
  Reality: `hr-dashboard.controller.ts:148-151` has a stub. `hr-offboarding.controller.ts`
  only has PATCH/POST routes, no `GET cases`. **CONFIRMED BROKEN.**

- **`/hr/pip`** — audit flagged `/api/hr-v2/pip/:id/complete`. Reality: confirmed
  missing. `PipController` has `:id`, `:id/progress`, `:id/acknowledge` but no
  `:id/complete`. Frontend `PIPPage.tsx:68` calls it. **CONFIRMED BROKEN.**

- **`/hr/referrals`** — audit flagged `/api/hr/referrals/:id`. Reality: `hr-gsd.controller.ts:36`
  has `GET referrals` and `GET referrals/boomerang` but no `POST` or `PATCH /:id`.
  Frontend `ReferralPage.tsx:51,63` calls both. **CONFIRMED BROKEN.**
